# Output 단일 반출 설계와 구현 추적 (#105, #109)

이 문서는 Output 단일 반출의 구현 계약이다. 실제 검증 결과는 아래 검증 기록에 있다.
선행 PR #104는 develop에 병합됐다. 이번 작업은 Shared 수신 경로 자체를 제거한다.

## 최종 사용자 흐름

1. Sandbox 바탕화면 `Output` 바로가기로 실제 Runner 세션 Output에 저장한다.
2. Runner 후보 보고/전체 목록 확인으로 Host가 결과 목록을 조회한다.
3. Host는 같은 HTTPS 업로드로 파일을 실행 금지 반출 대기 영역에 확보한다.
   확보는 다운로드 공개나 검사 통과를 뜻하지 않는다.
4. SecureArtifactScanner가 임시 수신본을 서비스 격리 경로에서 검사한다.
5. CLEAN으로 확인된 바이트만 다운로드에 자동 저장한다. 악성·오류·미확인은 차단한다.
6. 반출 확인·최종 승인·결과 알림창 대신 MCP가 완료 여부와 저장 경로 또는 차단 원인을 반환한다.
   정상 종료 시 나머지 Output에도 같은 절차를 적용한다. [응답 계약과 검증 범위](automatic-output-export.md).

## 종료 전 확보 계약

- 정상 종료 요청 및 Sandbox 창 닫기 감지 시 Runner TERMINATE보다 먼저 확보 단계를 수행한다.
- 안정화 이벤트만 믿지 않고 Output 전체를 재탐색한다. 기존 파일과 폴더째 들어온 파일도 포함한다.
- Runner는 해당 목록의 파일과 경로 핸들을 잠그고 그 목록에 묶인 후보 식별자를 발급한다.
- Host는 각 후보를 기존 일회용 HTTPS 업로드 토큰으로 수신하고 실제 크기와 해시를 기록한다.
- 이름·크기·잠긴 원본 SHA-256이 같으면 Host에서 다시 해시를 확인한 수신본을 재사용한다.
  이전 삭제 선택도 같은 내용에 한해 유지한다. Guest 해시는 검사 통과를 의미하지 않는다.
- 전송 뒤 Runner는 목록과 잠긴 파일이 여전히 일치하는지 재확인한다. 추가/삭제/변경,
  링크, 크기 한도, 미전송 파일, 연결 끊김은 확보 완료로 보고하지 않는다.
- 이 단계가 끝나기 전에 정상 종료를 진행하지 않는다. 실패 시 누락을 안내하고 이미 확보한
  사본은 실행 금지 영역에 보류한다. 자동 재전송/파일 변경 묵인/실패를 빈 목록으로 바꾸지 않는다.
- 강제 VM 소멸이나 Host 장애로 아직 전송되지 않은 바이트를 복구한다고 주장하지 않는다.
- 후보 이벤트 기반 사전 확보를 함께 적용해 창 닫기와 연결 손실에서 확보 가능한 범위를 넓힌다.
  사전 확보된 사본은 현재 목록/세대와 대조하며 최신 파일이라고 무조건 간주하지 않는다.
- Runner 세대가 교체되면 이전 잠금 ID와 확보 완료 상태를 새 세대에 재사용하지 않는다.
  이전 수신본은 보존하고 새 Output 목록을 다시 확보한다. 교체 전에 보낸 요청의 응답이
  늦게 도착해도 새 세대의 확보 완료로 인정하지 않는다.

## 경로와 책임

- Guest 원본: Runner의 세션별 `output` 하나. 바탕화면 바로가기는 같은 폴더를 가리킨다.
- Host 대기 영역: `Work/output/<세션>/...`, 실행 금지. 쓰기 가능 Host 공유 매핑을 만들지 않는다.
- 서비스 검사 사본: 기존 서비스 전용 Quarantine. scan-only 검사 계약은 재사용한다.
- 최종 저장: `Downloads/SandboxOutput/<세션>/<반출 ID>/...`.
- 기존 Shared 폴더의 잔여 파일은 자동 삭제하거나 새 Output으로 무검증 이관하지 않는다.
- Manager는 VM 수명주기만 담당한다. 통합 실행은 Shared 매핑/미러/별도 반출 API를 호출하지 않는다.
